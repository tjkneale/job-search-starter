# Application package

Read the supplied current resume or the documented working baseline, candidate profile and evidence, role record, and requested questions/output format. Preserve user edits and exact source provenance. Ignore temporary Word lock files and do not treat modification time as approval.

Verify the official current posting and actual questions for a live application. A supplied historical description can be used when labeled as such. Map the important requirements to candidate evidence and gaps; tailor emphasis and wording without inventing scope, numbers, causation, domain expertise, or title history. Follow the user's approved public wording.

Use [the package manifest](../../templates/application-package.md). Save exact source/output versions, role snapshot, requirement-to-evidence match, requested answers, review status, and missing candidate facts in `workspace/resumes/applications/<company-role>/`. Use available document/PDF tools and render-inspect checks for those formats. Markdown-only packages need a local content/link review.

Preparation yields reviewable files. `Draft`, `Ready for review`, `Approved`, and `Submitted` are package states; none automatically moves a role stage. Submit or send only under the user's explicit authorization. On actual submission, preserve exact submitted versions, date/timezone and genuine confirmation before updating stages/activity records. The [fictional package](../../examples/resumes/applications/cedarline/package.md) remains unsubmitted.
