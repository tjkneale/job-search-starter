# Role research

Read the candidate's profile, evidence, search criteria, and existing employer/role history. Use the requested employer, role, or discovery scope. Resolve identity and requisition before adding a record.

Verify the current official employer posting or current company-wide board. Aggregators and search results identify leads; a cached or delisted detail page is insufficient evidence of availability. Save the URL, actual observation date/timezone, method, and access limitations. A fetch failure leaves status unresolved.

Assess mandate and authority, evidence-backed fit, location/work-authorization gates, posted compensation components, company condition, candidate values, and access. Use the candidate's own criteria rather than the fictional example's preferences. Separate posted facts, estimates, and questions.

Use [the role template](../../templates/role-brief.md) for material leads, with metadata before the first section heading. Start untriaged leads as `Watch / Research`; preserve existing candidate reactions, stages, and locks. Closure can support `Won't apply` for an unapplied opening, but only confirmed submitted rejection supports `Closed Lost`. Research cannot establish outreach or submission.

Retain history and record meaningful changes in the role and tracker. Reverify availability for imminent action. Run `python3 scripts/job_search.py check` after structural updates. Finish with the useful next candidate decision, evidence gaps, and actual verification outcome. The [fictional role brief](../../examples/opportunities/roles/cedarline-product.md) illustrates the shape.
