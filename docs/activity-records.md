# Personal activity records

Use the [activity template](../templates/activity-log.md) to capture actual candidate actions with dates, purpose, sources, and completion state. The [fictional example](../examples/profile/activity-log.md) shows a completed conversation, a prepared application that was not submitted, and an unwatched resource remaining pending.

This is an evidence log, not an unemployment eligibility engine. If benefits reporting is relevant, the user must identify their jurisdiction, reporting week boundaries, current official requirements, and claim status. Verify those requirements with the responsible authority at setup and when they change; do not assume a universal count or qualifying category. This starter includes no state-specific rules, approved-activity determination, claim identifier, or filing automation.

Separate personally completed actions from assistant research, drafts, scheduled meetings, and prepared learning resources. Record the actual event date independently of capture date. A summary or assistant watching a video does not establish that the candidate watched it. Retain unresolved entries as pending; batch only the confirmations needed for the user's actual reporting requirements. Keep log completeness, claim filing, eligibility, and authority approval separate.

Save private minimal evidence. Genuine screenshots or correspondence can support real actions, but invented fixtures must never become claim evidence. If follow-up maintenance is requested, use [automation setup](automations.md); nothing is scheduled by this file.
